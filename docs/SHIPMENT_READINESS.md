# Shipment readiness assessment

This status compares the repository with `UPDATE.md`, including its primary engineering workflow and Phase 10 self-hosting requirements. It is a code review snapshot, not a claim that every product requirement is complete.

## Product shipment blockers

Persistent individual teammate conversations are implemented in the current workstream: conversation records bind a tenant, organization, teammate, assigned project, and durable session; message endpoints re-check membership and assignment; prompts use a bounded recent transcript; and the Teammates UI can resume or start a saved conversation. This is conversational continuity only and does not expose workspace tools through the direct chat path. Migration `0058` adds forced tenant RLS for the conversation binding. Unit coverage checks prompt bounds and send-route persistence/ownership; PostgreSQL coverage checks tenant isolation and assignment enforcement. Those tests still need CI execution before this feature is release-validated.

The central `UPDATE.md` workflow is not complete. The sandbox supports seeding a task workspace with caller-selected public GitHub files or private GitHub files through the active organization credential linked to that repository, pinned to one commit SHA and scoped through the delegated task's project handoff, with source provenance persisted. Full repository mode performs a shallow Git checkout after tree preflight, uses filtered temporary authentication, disables hooks and prompts, rejects unsafe paths, symlinks, submodules, and unsupported modes, and checks out only when the fetched commit matches the REST-pinned SHA. Repository files are streamed from Git objects without applying Git attribute filters, preserving raw GitHub blob bytes. Delivery compares changed files against GitHub tree blob hashes instead of trusting the mutable local `.git` directory. During an active delegated handoff, teammates can list/read files under `READ_ONLY` and write/delete files under `MODIFY_FILES`; writes and deletions pause while a verification approval is pending, approved, or running. Under `EXECUTE_COMMANDS`, teammates can request fixed test/build/lint/typecheck/security profiles, which require an owner/admin decision before the sandbox runs. The approval records the exact argv and workspace digest, and execution rejects a changed workspace. Tool invocation metadata and verification outputs are persisted.

PR #98 adds a task completion gate: acceptance decisions are bound to the current workspace digest, and tasks with handoffs require passing required verification runs against that same digest. Workspace fingerprint failures fail closed, workspace mutations reopen completed tasks, and migration `0057` places existing completed workspace tasks into review. Teammates can run bounded literal case-insensitive source search over their assigned workspace with `READ_ONLY`; search excludes `.git`, symlinks, NUL-containing files, and invalid UTF-8, caps directory entries/files/bytes/results/output, and labels repository text as untrusted. Before a task workspace exists, connected repositories now have separate path-only search at `/repositories/{id}/files/search` and bounded content search at `/repositories/{id}/content/search`. Content search resolves and pins all reads to one commit SHA, reports the related Git tree SHA, and scans deterministic regular blobs with allowlisted code/text extensions, up to 25 files, 64 KB per file, about 1 MB aggregate blob data, 20 matches, and 500 characters per snippet. Binary, NUL-containing, and known oversized files are skipped; results carry revision and scan counts, truncation status, and an untrusted-content label. `fetched_bytes` reserves the tree-reported blob size before each fetch so skipped or undecodable files still consume the aggregate budget. A 45-second request deadline, candidate/byte/result caps, or GitHub rate limit can limit coverage. This is not exhaustive indexing, and no code-search index or semantic search is provided.

For repository-backed workspaces, an owner/admin can use the task review page to inspect the diff and submit the displayed digest to create a Solvyn branch from the exact pinned source commit, commit up to 50 UTF-8 text file operations / 500 KB, and open a draft PR. A deletion is allowed only for a selected regular, non-executable text file present in the pinned source; unsupported missing paths remain blockers. The preview binds the current GitHub base branch as well as the workspace; a changed preview invalidates the delivery request. The endpoint will not merge. Changed executable files and edits to unselected existing paths are rejected. Each digest-bound delivery attempt is persisted with branch, commit, PR, and outcome status; repeat requests replay the saved creation result without claiming the PR's current state, or stop for recovery when a prior outcome is unresolved. If a GitHub write times out after it may have succeeded, the endpoint records an unknown outcome and recovery guidance rather than claiming no remote change was made. The task review page includes a bounded activity feed for task lifecycle events, acceptance-criteria decisions, dependency changes, tool records, verification runs, related handoffs and approvals, and delivery attempts across the task's descendants. Lifecycle events are captured atomically for task creation and status changes; existing tasks receive a point-in-time status baseline, not fabricated historical transitions. Tree traversal is capped at 500 tasks / 32 levels, and the feed is capped per source and overall. Live GitHub status refresh currently applies to the requested task's PRs; descendant PRs show saved delivery state without a live refresh.

## Repository inspection and dependency coverage

Repository inspection now loads the original root context files and supported dependency manifests at the root and one directory below. Root context files are prioritized; the 25-candidate cap includes context files such as `README.md`, and the response separately reports manifest and context candidate counts, scanned/omitted counts, and partial-coverage status. Per-file and aggregate read caps are 64 KB and 512 KB. Reads use the resolved default-branch commit, and the response includes both commit and tree revisions. Static direct dependency names are extracted from npm, Python, Go, Rust, Maven, Gradle, Ruby, and Composer manifests. This does not resolve versions, detect vulnerable/outdated dependencies, or provide a trusted dependency-update event source; dependency maintenance schedules remain reminders.

## Release decision

The Phase 10 Compose path and Kubernetes CI workflow are implemented, but neither a controlled Kubernetes deployment nor a deployment-specific restore drill has been recorded. Kubernetes deployment also requires the operator configuration listed above. The overall product is **not ready to ship as the AI engineering teammate described in `UPDATE.md`** until the repository-to-agent-to-sandbox workflow is completed, tenant isolation and operational gaps are addressed, and deployment validation is recorded. The exact release scope should not be represented as a complete implementation of the product brief.
